# AGENTS.md

Three independent npm projects, no workspace: `server/` (Express API),
`client/` (Vite + React + Mantine) and `api/` (TypeSpec contract → OpenAPI).
Install and run commands inside the project you touch — the root `package.json`
is tooling only (commitlint + husky + the one-command generation chain).

Requires Node >= 24 (`.nvmrc`); run `nvm use` first — the default `node` on PATH
can be much older (v12 in the provided sandbox).

## Commands

Server, from `server/`:

- `npm run dev` · `npm start` · `npm test` (`node --test`)
- `npm run lint` (oxlint) · `npm run coverage`
- `npm run migrate` — apply `src/db/schema.sql`; run before first start
- `npm run smoke`

Client, from `client/`:

- `npm run dev` — Vite on :5173, proxies `/api` → `http://localhost:3000`
- `npm run build` (`tsc -b && vite build`) · `npm run lint` (oxlint)
- `npm test` (Vitest); single file: `npx vitest run src/pages/landing/ui/Hero.test.tsx`
- `npm run generate:api` — regenerate the client SDK from `../api/openapi/openapi.yaml`

API contract, from `api/`:

- `npm run build` — `tsp compile .` → `openapi/openapi.yaml`
- `npm run lint` — `tsp format --check` + compile without emitting

Root: `npm run lint:last` checks the last commit message;
`npm run generate:api` repeats the whole generation chain in one command
(`api` build → `server` generate → `client` generate), and
`npm run generate:api:check` additionally fails if the generated output is not
committed.

## Rules not visible in code

- Env is loaded by Node via `--env-file-if-exists=.env` — do **not** add dotenv.
  Copy `server/.env.example` → `server/.env`.
- DB is built-in `node:sqlite` (synchronous; the experimental warning on Node 24
  is expected). `data/` is gitignored and auto-created.
- Migrations must stay idempotent at the SQL level (`CREATE TABLE IF NOT EXISTS`).
- Conventional Commits are enforced locally and in CI; header ≤ 72 chars, allowed
  scopes: `server`, `client`, `db`, `api`, `ui`, `ci`, `deps`, `docs`, `main`
  (`main` — для авто‑коммитов release-please); see `CONTRIBUTING.md`.
- CI `ci.yml` runs five jobs: `server` (`npm ci` → `lint` →
  `git diff --exit-code -- src/generated` → `test` → `migrate` → `smoke`),
  `client` (`npm ci` → `lint` → `test` → `build` →
  `git diff --exit-code -- src/shared/api/generated`), `api`
  (`npm ci` → `lint` → `build` → `git diff --exit-code -- openapi`),
  `docker` (`docker build` → run the container → wait for `/health`) and
  `commitlint`. `release-please` versions `server/` and `client/` separately;
  `api/` is not versioned.
- The root `Dockerfile` packages only `server/` (the client is a separate SPA,
  not served by Express). At container start the `CMD` applies the idempotent
  schema (`node src/db/migrate.js`) and then `exec`s the server, so the app
  boots on its own; `DB_PATH` defaults to `/app/data/prod.db`, meant for a
  mounted volume. Build context is the repo root — see `.dockerignore`.
- The API contract lives in `api/` as TypeSpec. `api/openapi/openapi.yaml` is
  generated and committed — never edit it by hand: change the `.tsp`, run
  `npm run build` in `api/`, and commit the regenerated file, or the `api` CI
  job fails on the diff. `docs/spec.md` stays the source of truth for *why*;
  `api/` for *what*. The whole chain (`api` build → `server` generate →
  `client` generate) repeats from the repo root in one command:
  `npm run generate:api` (`generate:api:check` also fails when the generated
  output is not committed).
- The client SDK is generated from that same contract:
  `client/src/shared/api/generated/` is produced by `@hey-api/openapi-ts`
  (`npm run generate:api` in `client/`) and committed — never edit it by hand.
  Change the `.tsp`, rebuild `openapi.yaml`, regenerate the SDK, and commit
  both, or the `client` CI job fails on the diff. Code outside the slice uses it
  only through `client/src/shared/api/index.ts`.
- Server artifacts are generated from that same contract too:
  `server/src/generated/` (`spec.js`, `types.js`, `routes.js`) is produced by
  `npm run generate:api` in `server/` (reads `api/openapi/openapi.yaml`) and
  committed — never edit it by hand. `spec.js` carries the schemas and the
  operation list, `types.js` — JSDoc types, `routes.js` — `createApiRouter(handlers)`,
  an Express router factory keyed by `operationId`. Request bodies are validated
  against `spec.js` with Ajv in `server/src/middleware/validate.js`; semantic
  rules that a schema cannot express (trim, booking window, real slot) stay in
  handlers. `server/src/app.js` mounts the router with the handlers from
  `server/src/routes/index.js`; operations without a handler answer
  `501 not_implemented`. Change the `.tsp`, rebuild `openapi.yaml`, regenerate,
  and commit, or the `server` CI job fails on the diff.
- `.github/workflows/hexlet-check.yml` is generated by Hexlet — do not edit,
  delete, or rename it (or the repo).
- `client/src/` follows Feature-Sliced Design: layers `app → pages → widgets →
  shared` (top to bottom). A slice may import only from layers **below** it and
  only through the slice's public API (`index.ts`). Layers and slices appear
  lazily, when first needed — no empty scaffolding. The router is `react-router`
  in Declarative mode: pages link with `<Link>`/`<NavLink>`, routing config lives
  in the `app/routes` slice, and route path constants live in `shared/routes`
  (both `widgets/header` and `pages/*` read them, so they cannot live above).

## Agent skills

### Issue tracker

Issues and specs live as GitHub issues in this repo, managed with the `gh` CLI. See `docs/agents/issue-tracker.md`.

### Triage labels

The five canonical triage roles, each label string equal to its name. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `GLOSSARY.md` and `docs/adr/` at the repo root. See `docs/agents/domain.md`.

### MCP servers

Конфигурация MCP-серверов лежит в [`opencode.json`](./opencode.json) в корне
репозитория. Render MCP берёт ключ из переменной окружения `RENDER_API_KEY` —
самого секрета в репозитории нет.
