# Как контрибьютить

## Соглашение о коммитах

Проект следует спецификации [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/).
Сообщения проверяются автоматически: локально — `commit-msg` хуком, в CI — job
`commitlint` (`.github/workflows/ci.yml`).

### Формат

```text
<тип>(<область>): <описание>

[необязательное тело]

[необязательные футеры]
```

- **Тип** и **область** — строчными буквами.
- **Описание** — в повелительном наклонении, строчными буквами, без точки в конце.
- **Заголовок** — не длиннее 72 символов.
- **Область** (`scope`) — необязательна, но если указана, то только из списка ниже.
- **Язык описания** — английский (как в существующих коммитах). Технически
  допускается и русский: регистр описания проверкой не ограничивается.

### Типы

| Тип        | Когда использовать                                      |
| ---------- | ------------------------------------------------------- |
| `feat`     | новая функциональность                                  |
| `fix`      | исправление бага                                        |
| `docs`     | изменения только в документации                         |
| `style`    | форматирование, пробелы (без изменения логики)          |
| `refactor` | рефакторинг без новой функциональности и без багфиксов  |
| `perf`     | улучшение производительности                            |
| `test`     | добавление или правка тестов                            |
| `build`    | сборка, зависимости, инструменты сборки                 |
| `ci`       | конфигурация CI (GitHub Actions и т.п.)                 |
| `chore`    | прочие изменения, не влияющие на код (например, `.gitignore`) |
| `revert`   | откат предыдущего коммита                               |

### Области (scope)

`server`, `client`, `db`, `api`, `ui`, `ci`, `deps`, `docs`, `main`.

Область `main` зарезервирована под автоматические коммиты release-please
(`chore(main): release ...`), вручную её использовать не нужно.

Область `api` — это контракт API на TypeSpec в `api/` (и собранный из него
`openapi/openapi.yaml`). Код маршрутов в `server/` идёт под область `server`.

### Ломающие изменения

Ломающее изменение помечается `!` после типа/области или футером
`BREAKING CHANGE:` в теле:

```text
feat(api)!: remove legacy booking endpoint

BREAKING CHANGE: POST /api/bookings больше не принимает поле timezone.
```

### Примеры

Хорошо:

```text
feat(server): add booking creation endpoint
fix(client): reset form after successful submit
docs: describe commit message convention
ci: validate commit messages in pull requests
chore(deps): bump express to 5.3.1
```

Плохо:

```text
Added endpoint            # нет типа и области, прошедшее время
fix: исправил баг.         # точка в конце, нет описания сути
FEAT(Server): Add stuff   # заглавные буквы в типе/области
update                    # нет типа
```

## Локальная настройка

Хук `commit-msg` ставится автоматически при `npm install` в корне репозитория
(через скрипт `prepare` и [husky](https://typicode.github.io/husky/)).

Проверить сообщение вручную:

```bash
echo "feat(server): add endpoint" | npx commitlint
```

Если нужно сделать коммит без проверки (не рекомендуется): `git commit --no-verify`.
